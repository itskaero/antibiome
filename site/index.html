Association, not causation

Comparisons carry their test and p value, and say plainly what they cannot show. Logistic regression is refused when there are too few events.

Small numbers flagged

The antibiogram counts the first isolate per patient and marks every cell under 30 isolates. Months with few patients say so.

CLSI M39 · days present

Missing stays missing

A value nobody recorded is never treated as “no”. Scores list the inputs they are missing, so an underestimate is visible.

FAQ

Everything you might be wondering about

Still have questions? Read the setup guide.

Does it need the internet?

No. Everything runs on the PICU PC with a local database. Internet is only used if you switch on AI questions.

Where is patient data stored?

In one SQLite file on the unit PC (%APPDATA%\Antibiome PICU\data), with a snapshot every day. Names and MRNs are kept apart from the analytics and never leave the PC.

Will it run on our old PC?

Yes. Windows 10 and 11 use the regular edition. Windows 7, 8 and 8.1 have their own edition, in 32- and 64-bit. It is the same app on an older engine that no longer receives security updates, so move to Windows 10 or later when you can.

Can staff use their phones?

Yes, over the hospital Wi-Fi. An administrator pairs each phone with a single-use QR code; staff sign in with their own accounts; phones lock after 5 minutes and store nothing about patients.

Does it tell us how to treat a patient?

No. Antibiome describes what the unit records and does — severity, use, susceptibility, adherence — for audit, quality improvement and research. Treatment decisions stay with the clinical team.

What do the scores mean?

PIM3 estimates risk of death for unit-level comparison (SMR). Phoenix (2024) is the international paediatric sepsis definition. Brighton PEWS describes deterioration. All are shown with their inputs and limits.

Can we bring in our old Antibiome cultures?

Yes. Export them from the old NICU app (Records → Export CSV) and use Settings → Import Antibiome cultures.

Which AI does it use, and is it required?

It's optional and off by default. An administrator can choose Claude (Anthropic) or DeepSeek to turn typed questions into queries you confirm. Only the question and field names are sent — never patient data.

What does it cost?

The source is on GitHub and the Windows builds are free to download. Ask your hospital's IT and information-governance teams before installing it on a clinical network.

Setup guide · version 0.1.0

Setting up Antibiome PICU

From an empty Windows PC to the first admission, then phones and optional AI. Allow about an hour, plus IT time for the network steps.

Requirements

  • One Windows PC in the unit (Windows 10 or 11 recommended; Windows 7, 8 and 8.1 have their own edition), left on during shifts. It holds the database.
  • BitLocker (or another disk encryption) on that PC — the database file is not encrypted by the app.
  • A Windows account per user, and screen lock.
  • Optional: staff phones on the hospital Wi-Fi, and internet access for AI questions.

Install on the PC

  1. Open the Download tab and pick the edition for the PC's Windows version: Windows 10 & 11, or the Windows 7 edition for Windows 7, 8 and 8.1.
  2. Download the installer (it picks 32- or 64-bit for you), or a portable file if you can't install software.
  3. Run it. If Windows shows “Windows protected your PC”, choose More info → Run anyway — the files are not code-signed yet.
  4. Open Antibiome PICU from the Start menu.

Building it yourself

On any Windows machine with Node.js 22:

git clone https://github.com/itskaero/antibiome.git
cd antibiome/desktop
npm install
npm run dist:win     # Windows 10/11, 32- and 64-bit
npm run dist:win7    # Windows 7/8/8.1 edition

The files appear in desktop\release\. Pushing a tag such as v0.1.4 builds every edition on GitHub Actions and publishes a release.

Where the data lives: %APPDATA%\Antibiome PICU\data\antibiome.db. To keep it elsewhere (for example an encrypted drive), set the ANTIBIOME_DATA_DIR environment variable before starting the app.

First run

  1. Create the unit: its name, the number of beds (used for occupancy), and your administrator account.
  2. Bring in history (optional). The original NICU web app is still available at legacy/ while units move over. Export your cultures there (Records → Export CSV), then in Antibiome PICU use Settings → Local database → Import Antibiome cultures.
  3. Or explore first. Load demo data fills an empty database with clearly labelled synthetic admissions. Use a separate data folder for this, not the live one.
  4. Check the disease modules (Modules & fields). Sepsis, pneumonia, GBS and DKA are built in; add fields later without breaking earlier records.

Daily use

Admit

Press A anywhere. MRN, sex, age, bed, source and primary diagnosis are all that is required; Ctrl + Enter saves. Admission vital signs and PIM3 are optional panels in the same sheet.

During the stay

  • Change respiratory support with one tap on the census board.
  • Start and stop vasoactives and antimicrobials on the patient page.
  • Record vital signs on admission, at a deterioration or at review — any subset is fine.
  • Daily reconcile (R) checks every bed's support and drugs in one grid.

Vitals, labs and scores

Press Record on the vitals card. Add Labs (lactate, PaO₂, platelets, INR, D-dimer, fibrinogen, fixed pupils) or PEWS to the same set when you have them. The app works out the Phoenix Sepsis Score for that moment and the worst in the first 24 h, and flags Phoenix sepsis and septic shock. Inputs that were not recorded count as zero, and the card says which ones are missing.

The therapy chart

At the top of every patient page: respiratory support, vasoactives and each antimicrobial across the days of the stay, cultures and complications where they happened, and vitals underneath. Hover any mark for exact times.

Finding past patients

Patients in the sidebar lists every admission, current and past. Search by MRN, name, diagnosis, ICD-10 code or bed, and filter by outcome or admission date. Other admissions of the same child are linked from the patient page.

Discharge

Choose the outcome and time; anything still running is closed at that time, and the sheet asks only for module fields still missing.

Phones on the hospital Wi-Fi

Off until an administrator turns it on. Phones open the app in their browser from the PC over HTTPS; the PC must be on with the app running.

1 · Ask IT for three things

  • A fixed IP address (or DHCP reservation) for the PC.
  • An inbound firewall rule for the port (default 8443), domain and private networks only:
netsh advfirewall firewall add rule name="Antibiome PICU phones" dir=in action=allow protocol=TCP localport=8443 profile=domain,private
  • A network path from the staff Wi-Fi to the PC (not from guest Wi-Fi).
Recommended: a certificate for the PC's address from the hospital's certificate authority, as a PFX file. Without it the app creates its own certificate and each phone shows a one-time warning.

2 · Turn it on

Settings → Phone access → On. The card shows the address (for example https://10.20.0.15:8443), the certificate's SHA-256 fingerprint, and Load hospital certificate…

3 · Pair each phone

  1. On the PC, press Pair a phone. A QR code and an 8-character code appear; they work once, for 10 minutes.
  2. On the phone, connected to the staff Wi-Fi, scan the QR code. If a certificate warning appears, check that the fingerprint starts with the characters shown on the PC, then continue.
  3. Name the phone (for example “Dr Khan's phone”) and press Pair phone.
  4. Sign in with your own username and password. Sign in again after 5 idle minutes or after closing the tab.

Managing phones

  • Revoke a lost or replaced phone in the device list; it is signed out at once.
  • Show patient names and MRNs on phones is off by default. Phones then show bed, pseudonymous ID, diagnosis and age.
Agree locally before go-live: personal phones on the clinical network need information-governance approval, and phones cannot block screenshots.

AI questions (optional)

Lets clinicians type a question such as “Pneumonia admissions this year: mortality by ventilation” and get a Research Explorer query to check and run. Only the question and the list of field names are sent; questions containing a recorded name or MRN are blocked; all numbers are calculated on the PC.

ProviderModelsKeyNote
Claude (Anthropic)claude-opus-5-5sk-ant-…Structured output enforced by the service
DeepSeekdeepseek-flash (default), deepseek-v4-prosk-…Servers in China — check your policy on international data transfer
  1. Settings → AI questions: choose the provider and, for DeepSeek, the model.
  2. Paste the API key and press Save key. It is encrypted with Windows' own key protection; each provider keeps its own key.
  3. Switch the card On. The question bar appears in Research.
The rest of the app works fully offline. If the PC has no internet, leave AI questions off.

Backups & data

  • A consistent snapshot is written to data\backups\ once a day; the last 14 are kept.
  • Settings → Back up now saves a copy anywhere you choose — keep one off the machine, for example on an encrypted USB drive in a locked cupboard.
  • To restore, close the app, replace antibiome.db with a backup copy, and delete antibiome.db-wal and antibiome.db-shm beside it if present.

Research export

Administrators and researchers can export one de-identified row per admission from Monthly report → Research export: day offsets instead of dates, no names, MRNs or free text, every module and vital-sign column, and a data dictionary saved alongside. Each export is logged.

Before any research use: get approval from your ethics committee. Groups under 5 patients can still be identifiable — don't share rare-diagnosis subsets outside the approved team.
